# 项目说明

> 非盈利开源项目（代码 MIT 许可证，故事版权归作者）。

## 愿景
“我的绿洲”是一个 AI 驱动冒险故事的平台：创作者用一份简单的规则集写出有规则、有目标、有结局的故事，玩家在桌面客户端里下载即玩。AI 负责讲故事，规则由代码保证公平。

## 产品形态
- **桌面客户端**：游玩、导入和上传故事都在这里完成，内置本地规则引擎和 AI 接入点。**不内置故事编辑器**：作者在客户端外制作故事包（手写，或把 [AI 创作指南](ai-authoring-guide.md) 复制给聊天 AI 让它生成），客户端负责导入、检查（看得懂的报错）、试玩、上传。界面由故事作者定义，没定义就用简约模板。
- **自建服务器**（阿里云 ECS，大陆节点）：账号、故事上传下载与审核、作品/下载记录/云存档等用户数据。
- **玩家自带 AI**：自己的 API Key 或本地模型；Key 只存本机钥匙串，不经过服务器。

## 核心概念
- **素材**：故事可以自带图片、立绘、背景、音乐、音效，并能随故事状态切换；之后还会支持作者设置的 AI 生图（玩家可关闭省钱）。
| 概念 | 说明 |
|---|---|
| **故事** | 一个能玩完的冒险；以“故事包”上传下载（规则 + 界面 + AI 设定 + 资源） |
| **规则** | 全部由作者定义。平台不内置骰子、属性、检定等固定玩法，只提供“记数值、触发动作和事件、可复现的随机数、判定结局、把动作交给 AI 用”这些基础能力；骰子、背包等是可选的官方模板 |
| **引擎** | 客户端里执行规则的部分，所有状态以它为准 |
| **界面** | 作者决定有哪些区域、哪些组件（叙述区、按钮、状态栏、NPC 对话框、地图……）；不设置就用简约模板 |
| **AI 接入点** | 作者决定哪些地方用 AI（叙述、NPC 对话、裁量按钮、生成描述），每处一张“任务卡”写清 AI 能做什么、能改多少；也可以完全不用 AI |
| **脚本** | 可选高级功能，用 JavaScript（以后加 Python、Lua）写复杂规则，在沙箱里运行 |
| **故事库** | 服务器上已审核的故事列表，下载即玩 |

## 和同类产品的区别
| | 我的绿洲 | SillyTavern 等角色聊天工具 | 纯提示词 AI 文字冒险 |
|---|---|---|---|
| 目标 | 玩完一个故事 | 和角色聊天 | 自由发挥 |
| 规则 | 作者自定义，引擎强制执行 | 主要靠提示词 | 全靠模型自觉 |
| AI 的权限 | 作者用任务卡限定，越权被拒 | 不限 | 不限 |
| 界面 | 作者自定义 | 固定聊天界面 | 固定 |
| 创作 | 标准故事包格式，可让 AI 照规范生成；客户端检查并大白话报错 | 角色卡 | 写提示词 |

## 目标用户
- **玩家**：喜欢有挑战、有结局的互动故事，有自己的模型 Key 或本地模型。
- **创作者**：会写故事、想加数值和规则，但不想开发完整游戏。
- **规模预期**：几千到几万注册用户。

## 暂定事项
- 故事包后缀 `.oasis`；主库暂不收 `mature`；AI 默认权限 1 级；后端 Node.js + TypeScript；英文名 My Oasis。

## 最高原则
1. **每一处内容都由作者标明“固定”还是“AI 处理”，没标的一律固定。**
2. **玩家不能超出故事规范**：只能做故事里声明的动作；只有作者开启的地方才能自由打字，打的字要么对应到声明过的动作，要么得到作者写好的“做不到”回应；玩家想让 AI 改数值、跳结局、无视规则，都会被引擎拦下，AI 只能在作者给的权限内回应；玩家只能改外观，不能改规则、状态和存档（存档有校验，改过就读不了）。

## 原则
- 规则由作者定、引擎说了算，AI 只能在作者给的权限内行事。
- Key 和隐私留在玩家电脑上。
- 服务器保持轻量，接口抽象好，随时能扩容。
- 遵守大陆法规：实名、备案、内容审核，不做成人内容。
